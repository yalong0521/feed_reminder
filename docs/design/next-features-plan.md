# 奶点记下一阶段功能设计

2026 年 10 月 3 日。本文先定义产品、界面和交互规则，再按项实现。目标是减少每餐的操作、让记录可以带走、让提醒更灵活，并保持当前离线使用与日光手账风格。用户已确认桌面卡片第一版优先鸿蒙。

## 共同约定

- 保留计时、记录、设置三个主入口；沿用 AppPalette、AppTypography、AppButton、AppSurface、现有日期选择器及奶量输入组件。
- 主操作保持一滑记录，辅助操作使用独立按钮，避免与滑块手势冲突。浅深色、小屏、横屏、大字体、键盘及读屏同等可用。
- 表单取消不改变数据；成功后才更新完成状态；失败保留输入并允许重试。保存中阻止重复提交。
- 统计和卡片展示已记录的数据，不把 0 mL 解释为实际没喝奶，不根据统计自动修改提醒策略。

## 1 本次奶量快速调整

### 产品

默认奶量继续用于后续每餐。用户可以在计时页临时改变本次奶量，范围仍是 0–2000 mL 整数；不修改设置中的默认值。临时值切换页面后保留，成功记录后清除，下一餐重新使用默认值；保存失败保留临时值。应用重新启动不保留未提交的临时选择。

### UI

滑块附近增加独立的“本次奶量 · 120 mL”调整入口；紧凑横屏使用同排独立按钮，保留倒计时可读空间。沿用现有奶量编辑面板，提供输入、±10 和常用量；标题为“调整本次奶量”，说明“仅用于下一条记录，默认奶量保持不变”。底部“取消／使用此奶量”，另提供“恢复默认”。滑块说明同步显示实际将保存的奶量。

### UX

点击调整入口 → 修改 → 确认回到计时页 → 滑动记录。取消不改变当前临时值；恢复默认直接清除临时选择。记录与调整不能同时提交，存储失败时保持原选择和错误反馈。补记继续使用全局默认值，与当前计时页的临时选择独立。

### 验收

验证默认 120、临时 90、第一餐 90、第二餐恢复 120；取消、撤销、失败重试、设置变化和屏幕切换均不错误修改默认值。

## 2 备份 恢复与 CSV 导出

### 产品

第一版提供喂奶记录的完整 JSON 备份、合并恢复与 CSV 导出。设备提醒、外观和授权设置保留本机值，并在页面明确说明。恢复不清空已有记录：同 ID 同内容跳过，同 ID 不同内容保留本机版本，新 ID 加入。导入文件先完整验证，再一次性保存；不接受部分损坏文件。

### UI

设置增加“数据管理”入口，进入独立页面。顶部显示当前记录数量和覆盖日期；依次展示“备份记录”“从备份恢复”“导出 CSV”。恢复选择文件后显示预览：文件日期范围、总条数、将新增条数、重复条数和冲突条数，再显示“合并恢复”。

### UX

使用系统文件选择器读取与保存，用户取消选择不报错。备份可恢复，CSV 用于阅读和整理，两者用途分别说明。损坏、版本不兼容、超限及写入失败显示明确原因；恢复失败原历史不变。确认恢复后按实际合并结果反馈，导入中的并发操作需按当前已保存记录再次去重。导入未来时间的已有历史可以保留，统计继续过滤尚未发生的时间。

### 验收

往返导出导入保持 ID、时间与奶量；重复导入幂等；同 ID 冲突不覆盖；损坏与中途保存失败不污染现有记录；CSV 支持中文和安全单元格；系统文件取消及不可用状态有反馈。

## 3 稍后提醒

### 产品

到点且本次提醒未停止时，允许选择 10、20、30 分钟后再次提醒。只改变当前周期的提醒时刻，不新增记录、不修改上次喂奶时间或全局间隔。延后结果绑定记录 ID、原时间及当前间隔，重启后仍有效；新一餐、修改当前周期时间或间隔后按新的周期计算。停止本次提醒后不再延后。

### UI

超时状态的“停止本次提醒”旁增加“稍后提醒”。弹出面板列出三个选项，说明从确认时起计算且“不会新增喂奶记录”；避免用户停留在弹窗时显示过期的预计时刻。延后后计时页显示“已延后提醒”和实际下次时刻；保留上次喂奶时间及正常记录入口。

### UX

选择延后 → 持久化成功 → 停止当前声音并替换系统提醒 → 显示新倒计时。持久化失败不能假装已经延后；声音或系统投递失败沿用现有提醒错误提示及重试机制。到达延后时间重新提醒，夜间静音照常生效。反复延后从操作当下计算；补记更早记录、仅改奶量不取消延后。撤销新记录恢复原周期时可恢复仍匹配的延后状态。

### 验收

覆盖延后与到期、重启、静音、停止提醒、新记录与撤销、仅改奶量、改时间或间隔、存储失败和并发请求；不能产生额外喂奶记录。

## 4 鸿蒙桌面卡片

### 产品

第一版提供一款 2×4 鸿蒙服务卡片，显示最近喂奶时间与奶量、记录日总量与次数、下一次提醒的绝对时间。点击进入应用计时页，“记录喂奶”打开应用内确认面板；卡片自身不直接写入一餐。无记录和未准备好时有独立状态。

### UI

使用与应用一致的暖纸底、陶土强调色和清晰数字层级，跟随系统浅深色。左侧最近一餐、右侧指定日期汇总，下方下一次提醒和记录按钮；固定显示数据所属日期与更新时间，避免系统未刷新时过期的“今天”造成误解。停止提醒显示“本次提醒已停止”。

### UX

记录、修改、删除、恢复和提醒调整成功后更新快照；首次添加卡片读取最近可用快照。卡片进入应用后显示最新数据。应用不运行时不承诺秒级倒计时；卡片刷新失败不影响喂奶记录保存。隐私门禁通过且记录可读取后才发布用户数据。

原生存储采用单写者：应用独占摘要 Preferences，卡片扩展独占实例索引 Preferences，各自通过原子替换的 JSON 文件向另一进程提供只读投影，避免跨进程共享 Preferences。

### 验收

验证快照、空状态、跨天文案、延后和停止状态、冷启动入口、更新失败隔离、原生注册与构建；桌面刷新和系统行为需要在目标鸿蒙设备上单独验收。

## 5 历史查询与统计增强

### 产品

历史可查看指定一天或指定日期范围，随时清除筛选回到全部。统计保留近 7／30 天，增加自选日期范围（最多 366 个自然日）。增加单餐平均奶量和平均喂养间隔；单餐平均仅使用奶量大于 0 的记录，间隔仅取范围内相邻有效时间记录，少于两条时显示暂无。

### UI

记录页顶部只增加一个“查询日期”入口，弹窗可选某一天或日期范围，生效后显示范围、命中数和“清除”。统计范围按钮增加“自选”；结果标题明确日期范围与自然日天数。新增指标沿用开放式数字分组，手机自动换行。超过 30 天的统计保留完整范围摘要，日柱图每页最多 30 天，提供前后翻页及图表日期范围，默认显示最近一页，避免 366 个键盘停靠点。

### UX

选择开始／结束日期 → 校验范围 → 应用。开始不能晚于结束，结束不能晚于今天；取消保留之前范围。筛选无记录展示明确空状态与清除入口，不能误显示为所有历史为空。范围切换后将所选日期限制在有效范围内，键盘焦点继续滚入可见区域。

### 验收

覆盖边界日、跨年闰日、本地时区、未来记录过滤、0 mL、空范围、同时间记录、少于两餐、自选范围切换、清除和大字体长范围布局。

## 实施与验证顺序

1. 各项设计与接口约定明确后，按独立文件范围并行实施。
2. 针对数据丢失、计时错误和用户主流程编写回归测试；每项先完成专项验证。
3. 合并后统一跑静态分析、全量测试、Web 预览和可用的原生构建；实看手机、横屏及大字体页面。
4. 更新使用说明，明确桌面卡片及真实设备尚未验证的部分，不以单元测试替代真机结果。

鸿蒙卡片已完成 ArkTS 页面、资源、扩展注册、快照与入口桥接；Dart 接口及应用联动测试通过。该阶段尚未配置 Flutter-OH / DevEco SDK，未执行 HAP 编译与真机验收；后续构建与安装进展见本文“鸿蒙构建与设备安装验收”。应用政策文案已更新，托管声明本次未发布。

## 整体 review 后的交互与可靠性补充

1. 读取失败 → 明确显示“记录暂时无法读取” → 点击“重新读取记录” → 恢复原有历史与计时。读取期间按钮禁用；计时、历史、统计、数据管理和侧栏使用一致的未知状态，不显示假的零值，不取消系统已有提醒。浏览器已检查深色 365 宽度竖屏和 640×280 横屏；组件测试另覆盖 320×280、两倍文字尺寸。
2. 停止提醒 → 显示“正在停止提醒…” → 保存失败时显示“重试保存停止状态” → 成功后显示“本次提醒已停止”。当前声音及时停止，错误不会被不相关记录操作清除，卡片只同步已保存的确认结果。
3. 选择备份 → 完整验证 → 合并预览 → 再次按当前历史验证并原子保存。新增记录后的完整 JSON 必须仍满足 10 MiB / 50,000 条的可备份限制；普通记录不受导入上限限制，既有超限历史不删减。容量与去重结果只在历史变化时重新计算。
4. 日期弹窗与统计页防重复打开；平均间隔改为一次遍历计算。卡片修复更新失败、撤销、旧刷新覆盖新快照和跨夏令时偏移问题。

整体 review 阶段验收：474 项 Flutter 测试通过、10 项鸿蒙专用测试跳过，静态分析无问题；10 项使用内存平台替身的 Node 原生控制流测试通过。Web 预览及 Windows Release 构建成功。页面审查未发现新增布局阻断，错误恢复有清晰且可执行的入口。该阶段尚未执行鸿蒙 ArkTS/HAP 编译和设备功能验收。

测试版已通过 `aa start` 成功启动，设备任务状态确认位于前台，进程持续运行；真实手机截图 `build/ohos_preview_launch.jpeg` 显示设置页正常渲染。启动与基本页面显示验证通过。

设备日志 `build/ohos_preview_launch.log` 中，后台代理提醒调用返回 `1700002` / `reminder_limit_exceeded`（后台提醒额度受限），应用已捕获原生错误，未闪退。当前 `.dev` 调试签名 Profile 的 `appServicesCapabilities` 为空，未包含代理提醒开放能力；原应用已获批的能力不会自动继承到新标识，需要配置测试身份对应能力后再验后台通知。错误码本身不足以确认唯一原因，系统配额仍需核查，后台提醒尚未验收通过。桌面卡片渲染与更新、系统文件选择器、隐私托管及 API 17 兼容性仍待专项验收；本轮没有修改提醒算法、申请新账号、发布商店包或托管声明。
